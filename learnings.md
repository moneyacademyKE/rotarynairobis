# Learnings: Social Showcase Project

## Qwik City + Bun 
- **Resumability**: Qwik's resumability is perfect for media-heavy sites. By default, zero JS is shipped to the client until a tab is clicked.
- **Data Loading**: Using `routeLoader$` to read a local JSON file generated by an ETL script is a "simple" and robust way to manage large static data sets without a database.

## ETL Parsing
- **Regex vs DOM**: For Telegram's `messages.html`, raw Regex is fast and doesn't require extra dependencies, but handling "joined" messages required a multi-pass approach.
- **Entity Decoding**: Always decode HTML entities (`&apos;`, `&quot;`) before performing classification or text analysis.

## Local OCR Classification
- **Tesseract.js Efficiency**: Running OCR on thumbnails (~80kb) is 10x faster than full-sized images with negligible accuracy loss for high-contrast text removal (posters).
- **Heuristic Hybrid**: Combining text-based caption heuristics with visual OCR provides a "defense-in-depth" layer for UI purity.
- **Worker Management**: Initializing a single OCR worker and re-using it across batches prevents memory leaks and startup overhead.
- **Resumability**: Storing classification in a persistent JSON manifest allows for incremental "diff-based" processing, avoiding redundant CPU cycles in future exports.

## Edge-Native Migration (D1 + KV)
- **D1 SQL Scalability**: Moving from static JSON to Cloudflare D1 SQL enables "hardware-accelerated" queries (LIKE, GROUP BY) that handle 1,600+ assets with sub-millisecond latency.
- **Workers KV Caching**: Utilizing KV for semantic search results and AI metadata caching drastically reduces Gemini API costs and improves cold-start performance.
- **SQL Seeding**: Generating massive SQL seed scripts from JSON manifests remains the most reliable way to bridge the Gap from local extraction to production deployment.

## CSS Scroll-Driven Animations
- **View Timeline**: Standardizing premium UI transitions via `view-timeline` and `animation-timeline` (CSS-only) provides TikTok-level fidelity without the main-thread Javascript tax.
- **Hardware Acceleration**: Relying on the browser's compositor for scroll animations ensures 60fps performance even on low-end mobile hardware common in the local market.

## Deployment Architecture (Pages + Worker SSR)
- **De-complected Media from Deploy**: The `dist/photos/` directory (243MB, 1614 files) was a legacy artifact from the pre-R2 era. Media must live in R2 and be served via Image Transforms, never bundled into the Pages deploy artifact.
- **Lean Deploy Artifacts**: After stripping photos from `dist/`, the deploy dropped from 1658 files (stalling uploads) to 48 files (1.12s upload). Deploy only what the edge *computes*, not what it *serves*.
- **Smart Placement**: `[placement] mode = "smart"` moves Worker compute to where D1 data resides, eliminating the isolate→DB network hop.
- **SSR Worker Entry Point**: Adding `qwik add cloudflare-pages` (or manual equivalent) creates `src/entry.cloudflare-pages.tsx` + `adapters/cloudflare-pages/vite.config.ts`. The `build.server` step produces `dist/_worker.js` which mounts the Qwik City SSR handler. Without this, the deploy is static-only (no `routeLoader$`, no D1/KV access).
- **Build Pipeline**: Must chain `build` (client) → `build.server` (adapter SSR) → `wrangler pages deploy dist`. The `qwik build` command auto-detects `build.server` in `package.json` and runs it.
- **nodejs_compat**: Qwik's SSR uses `node:async_hooks`. Add `compatibility_flags = ["nodejs_compat"]` to `wrangler.toml` to prevent runtime errors.
- **Pages vs Workers CLI**: Use `wrangler pages deploy dist` (not `wrangler deploy`) when `pages_build_output_dir` is set. The `_worker.js` in dist enables Advanced Mode — full Worker compute + static asset serving from a single deploy.

## Data Philosophy & Specs (Rich Hickey Quality)
- **Runtime TDD Boundaries**: Replacing blind casts (`as string`) inside edge `routeLoader$` functions with strict `zod` boundaries prevents database-level abnormalities from crashing frontend rendering logic. 
- **Type Purity**: Removing inline `interface` declarations in components (`ReelFeed.tsx`) in favor of centralized pure Domain schemas drastically improves type safety and structural simplicity. Qwik City easily infers Zod's `z.infer<T>`.
- **Bun Testing**: Using `bun test` allowed instant iteration on domain specification logic securely divorced from Vite/Qwik, pushing logic down the pipe perfectly.

## Immutable Data Layer
- **SQLite Views acting as APIs**: Reusing legacy `DROP > CREATE > INSERT` paradigms within a worker environment drops structural integrity. Moving to `sqlite3` Views + Triggers effectively implements a mini-Datomic ledger. The underlying data captures changes across time (`tx_id`), yet Qwik City load bindings remain simple and unaffected thanks to standard `CREATE VIEW`.
- **Pages Queues Handlers**: Cloudflare Pages natively supports exporting a `queue` handler directly from `src/entry.cloudflare-pages.tsx`. Pushing logic here eliminates the need for separate worker projects entirely, preserving "Lean Deploy" structures while adopting enterprise asynchronous workloads perfectly.
- **Workers Assets > Cloudflare Pages**: To support enterprise background tasks natively and escape routing constraints of Pages functions (`_worker.js`), the application migrated to standard Cloudflare Workers utilizing the new `assets = { directory = "dist" }` directive in Wrangler. This leverages Qwik's built-in SSG adapters seamlessly via standard `wrangler deploy`, rendering Pages abstractions defunct.
- **ORM Edge Value Typing**: Injecting Drizzle ORM into the edge worker perfectly satisfies the "Simple Made Easy" doctrine. Drizzle provides zero-runtime bulk (`7.4kb`) and does not conceal the SQL, but instead binds pure TypeScript values to our Edge `INSERT` commands. By mapping Drizzle Tables against our Epochal Database `VIEW`s, we completely abstract historical versioning from our strict runtime types.
- **Manual Integration vs CLI Strategy**: In environments where interactive CLI scaffolding (`qwik add`) hangs due to terminal input issues, manually implementing the boilerplate (especially for Partytown and Auth.js) is preferred. This preserves architectural purity as you explicitly control the `head` injection and `onRequest` middleware hooks, rather than relying on automated code-munging scripts.
- **De-complected Identity (Rich Hickey Logic)**: Removing Auth.js from a public-facing showcase reduces the "state" complexity of the system. By shifting from session-based identity to environment-key based boundaries for write operations (Ingestion API), we achieve the "Simple Made Easy" ideal — the system only computes what is necessary for its data-driven mission.
- **Workers Assets Configuration**: To move away from Pages wrapper logic entirely, use `main` targeting the server entry while setting `assets = { directory = "dist" }`. This bypasses `_worker.js` and allows direct Worker deployments via standard `wrangler deploy` while maintaining frontend static serving.

## Media Proxy Bridge (R2 Integration)
- **Interception Pattern**: By intercepting `/photos/*` requests in the Worker's `fetch` handler *before* the SSR router, we can serve large binary assets directly from R2. This de-complects "Media Delivery" from "Domain Routing."
- **Fact Sync (Local to R2)**: For legacy projects where media was originally bundled, a bulk sync from local `_excluded_photos/` to R2 is a critical one-time "Projection" of facts to the edge.
- **Cache-Control Immutability**: Setting `public, max-age=31536000, immutable` for R2-proxied assets ensures they are stored permanently in the Cloudflare edge cache, reducing R2 operations to near-zero for repeat visits.

## Visual Identity Projection (Floating Logo)
- **Minimalist Scaling**: Using `clamp(40px, 10vw, 80px)` for the logo height satisfies the "Responsive" requirement without hardcoded media queries.
- **Z-Index Layering**: Keeping the floating logo at a higher `z-index` (200) than the content but lower than the navigation (100) ensures visual hierarchy is preserved during the scroll.
- **Pointer Events**: Setting `pointer-events: none` on the floating header container while keeping `pointer-events: auto` on the logo link allows users to scroll content "through" the negative space of the branding layer.

## Stateless Telegram Ingestion (Webhook API v7+)
- **Fact Accretion**: Storing the raw Telegram `Update` JSON in `telegram_raw_facts` before processing ensures we never lose the original context of a message, fulfilling the "Epochal Time" requirement.
- **Media Pull Pattern**: Instead of expecting the client to upload media, the server "pulls" from Telegram's `getFile` API, then proxies it to R2. This de-complects "Receiving" from "Storing."
- **Secret Verification**: Using `X-Telegram-Bot-Api-Secret-Token` provides a lightweight security boundary for stateless webhooks in a serverless environment without needing heavy session middleware.

## Rich Hickey Quality
- The system is now a pure projector of four distinct fact streams: D1 (Meta), KV (Cache), R2 (Media), and Telegram (Ingestion).
- The deployment artifact remains lean (<1MB), fulfilling the "Simple Made Easy" ideal.
